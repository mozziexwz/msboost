# MSBOOST

面向 msboost.de 的登录制 Mieru 转发销售站。网站使用 D1 保存业务记录，R2 保存 AES-GCM 加密后的付费配置；运营 VPS 运行一次性 SSH 作业服务，中转 VPS 运行独立 `msboostgost.service`。

## 已实现

注册邮箱验证码可在后台独立启停，默认开启。关闭后仍限定 QQ 邮箱，并继续检查邀请码开关；邮件未配置也可普通注册。找回密码始终校验邮箱验证码。管理员保留邮箱必须通过验证或初始化密钥建立账号。

- QQ 邮箱验证码注册、可开关邀请制、可在后台启停 Turnstile、登录失败 IP 封禁、管理员与单客服权限。
- 免费一次性 DD / Mihomo Mieru 部署 / UTC+8 校时；原始配置只留作业内存 30 分钟，不写本站持久存储。SSH 密码不入数据库、不写日志、不安装客户管理 Agent。
- 后台套餐、一次性免费天卡、1/7/30 天卡、订单、易支付 V1 MD5 验签与主动查单、退款结果登记。
- 每客户每线路一个转发；该转发剩余时间严格大于 30 天时禁止购买。到期按服务器 UTC 时间判断，不依赖网页倒计时。
- 每条线路可由后台设为“必须使用客户自备前置机”；此时直连中转配置禁止下载，客户部署前置机后才能取得前置链路配置。
- 付费配置下载、可选自备前置机部署、工单、知识库、状态与探测记录、公告、政策编辑、审计。
- 配置到期立即失去下载权限，正常每 60 秒清理对象；对象存储失败保留删除队列重试。续费不会恢复已删除的文件，需重新上传。

## 上线前必须配置

1. 网站环境按 `.env.example` 设置。`APP_ENCRYPTION_KEY` 是随机 32 字节的 64 位十六进制值，必须独立安全备份，不可随意替换。`OWNER_EMAIL` 为你的 QQ 邮箱。邮件尚未配置时，可设置随机 `ADMIN_SETUP_TOKEN`（至少 32 位），通过登录窗口的“首次管理员初始化”输入该密钥、指定邮箱和新密码创建管理员；创建后此入口停用，请删除部署环境中的初始化密钥。也可在邮件接通后验证指定邮箱注册管理员，无需邀请码。
2. 在运营 Linux VPS 按 `ops/install-worker.sh` 安装作业服务，填写 `/etc/msboost-worker.env`，通过受信任 HTTPS 域名反代本机 8788，参考 Nginx 示例。网站与作业服务的 WORKER_TOKEN 必须相同。新版支持在后台“站点设置 → 邮件发送”填写 SMTP，授权码加密保存。QQ 邮箱使用 smtp.qq.com、465、SSL/TLS，账号与发件人填完整邮箱，密码栏填 SMTP 授权码。先保存并发送测试邮件，再开启验证码邮件。SMTP 可留待以后配置，邮件关闭不影响已有账号登录；注册和找回密码暂停。使用此后台配置前必须更新运营机 worker.py。
3. 配置 Turnstile 的真实站点密钥、服务端密钥和允许域名。私有预览不能替代面向客户的公开域名，生产收款回调和中转心跳须能到达站点。
4. 后台初始化套餐与政策草稿，填写实际价格、退款规则、经营主体、联系邮箱后启用销售。没有商户资料时不会伪造收款成功。
5. 易支付选择支持 V1 `submit.php` / `api.php?act=order` 与 MD5 签名的平台，填写网关、PID、KEY。并非所有称为易支付的平台都兼容；V2 RSA 需另写适配。修改网关前处理所有待支付订单。退款入口只登记已在支付平台执行的退款结果，不会自动退款。
6. 后台创建真实线路，设置公网地址、独立可用端口范围和测速目标。在每台中转 Linux VPS 安装 `ops/install-node.sh`，填写 `/etc/msboost-node.env` 中的线路令牌并启用 `msboostgost.service`。不会停止服务器已有的 `gost.service`。
7. 放行所需 TCP/UDP 端口及云安全组。客户 VPS 使用 root 或无密码 sudo。前置机安装的是业务转发服务 `msboost-front.service`，不是管理 Agent。

## 运维边界

- 中转每 20 秒获取授权，单规则独立进程，在到期时终止已有连接；网站失联超过 180 秒也会断流。禁用账户或暂停规则通常下一次心跳生效。为控制进程开销，单机默认最多 200 条规则，扩容前需压测。
- 状态页区分进程状态与探测结果；延迟/丢包为中转到后台指定目标的 ICMP 测量，不代表每位客户的端到端游戏质量。
- GFW 域名拒绝规则不是游戏白名单，不能保证客户只能访问游戏。客户拥有 root，能够修改自己 VPS 的规则。加密转发也不能在中转端判断具体访问网站。
- DD 默认关闭。必须先在可丢弃 VPS、有云控制台和备份的条件下测试再启用 `DD_ENABLED`。脚本准备成功不代表重装成功；新 SSH 指纹必须再次独立核对。上游多阶段重装脚本不是由本站完整固定版本的供应链。
- 后台可下载口令加密的业务备份，并在校验后恢复站点设置、用户、线路、转发、订单和财务记录。备份包含同站点 R2 对象引用，不复制配置文件内容；已删除的配置不能靠备份复活。仍应另行启用平台级灾备，并单独保管加密主密钥。正式营业前必须演练恢复。
- 真实 SMTP、Turnstile、支付渠道、Linux/systemd/SSH、域名及灾备恢复仍需部署环境验收。仓库测试使用模拟外部服务，不声称已做真实收款或远程 DD。
